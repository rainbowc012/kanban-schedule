# Kanban card movement

## Decisions

- 카드 이동은 클릭 기반이다. 카드를 선택하면(하단 작업 창에 상세가 뜸과 동시에)
  그 카드에만 이동 버튼이 나타난다. 화살표 키(←/→)를 보조 입력으로 둔다.
- 계획 상태의 카드는 실행으로만, 완료 상태의 카드는 실행으로만 이동 버튼을 가진다.
  실행 상태의 카드는 계획·완료 양쪽으로의 이동 버튼을 가진다.
- 드래그 앤 드롭은 PoC 범위에서 채택하지 않는다.

## Boundaries

- 카드가 선택되지 않은 상태에서는 이동 버튼을 렌더링하지 않는다.
- 이 결정은 계획/실행/완료 사이의 이동에만 적용된다. 작업 등록·수정·삭제 폼의
  입력 방식에는 적용되지 않는다.

## Why

카드는 제목만 보이도록 한다는 제약(PRODUCT.md 경험 원칙)과 상시 노출되는 이동
버튼이 함께 있으면, 좁은 열에서 버튼이 제목 폭을 잠식한다. 선택 시에만 노출하면
평상시 카드는 제목만 남고, 이미 배정된 "카드 클릭 = 선택" 동작 위에 얹히므로
사용자가 새로 배울 조작이 늘지 않는다.

드래그 앤 드롭은 한 작업이 평생 겪는 이동이 2~3회뿐이라 이동 속도의 이득이 적은
반면, 접근성·터치·자동 스크롤 처리와 클릭-드래그 구분 임계값까지 구현 비용이
크다.

## Reconsider when

- 작업 하나가 하루에도 여러 번 이동하는 사용 패턴이 관찰되는 경우
- 여러 작업을 한 번에 옮기는 요구가 생기는 경우

## Still-rejected alternatives

- 드래그 앤 드롭 — 이동 빈도 대비 구현·접근성 비용이 크다는 이유로 PoC에서 제외;
  실사용 빈도가 예상보다 높아지면 재검토.
- 카드에 이동 버튼 상시 노출 — "제목만 보이는 카드"라는 제약과 충돌해 기각.
