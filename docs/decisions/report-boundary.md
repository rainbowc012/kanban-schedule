# Report boundary (완료 작업 보고 경계)

## Decisions

- 완료 열의 기본 표시와 주간보고의 완료 목록은 보고 시작일 이후에 완료된
  작업만 포함한다.
- 보고 시작일은 사용자가 주간보고 패널의 Report 버튼을 눌러야만 앞으로
  움직인다. 달력 요일에 맞춰 자동으로 넘어가지 않는다.
- Report를 누르면 보고 시작일은 "누른 날짜"가 아니라 "누른 날짜가 속한
  달력 주(월~일)의 월요일"로 설정된다.
- Report는 데이터를 지우지 않는다. 완료 열의 "전체 보기" 토글로 보고
  시작일 이전 것도 언제든 다시 볼 수 있다.
- 진행·보류 목록은 보고 시작일의 영향을 받지 않고 항상 현재 상태를 그대로
  보여준다.

## Boundaries

- 이 규칙은 완료(done) 작업에만 적용된다. 진행·보류는 대상이 아니다.
- "전체 보기"에서 쓰이는 달력 주(월~일) 구분선은 이 결정과 무관한 별개의
  개념이다 — 그건 훑어보기용 시각적 그룹핑일 뿐, 보고 시작일과 연동되지
  않는다.

## Why

처음엔 완료 열을 화~월 기준으로 매주 자동으로 넘기는 안을 검토했으나,
연휴나 휴가로 그 시점에 앱을 안 열면 지난주 기록을 사용자가 보지도 못한
채 화면에서 빠지는 위험이 있었다. 그래서 자동(달력 기반)이 아니라
사용자의 명시적 확인(Report 클릭)으로만 경계가 움직이게 했다.

그다음 "보고 시작일 = 클릭한 날짜(오늘)"로 짰더니, 이번 주 중간에(예:
목요일) 눌러도 이번 주 월~수에 이미 완료한 것까지 같이 사라지는 문제가
생겼다. 아직 보고 안 한 이번 주 성과가 사라지면 안 되므로, 경계를
"오늘"이 아니라 "이번 주(클릭 시점이 속한 주)의 월요일"로 잡아 이번 주
전체가 항상 보존되게 했다.

## Reconsider when

- 사용자가 한 주에 여러 번 Report를 눌러야 하는 패턴이 생기는 경우 (지금은
  주 1회 클릭을 가정)
- 실수로 누른 Report를 되돌리고 싶다는 요구가 반복되는 경우

## Still-rejected alternatives

- 화~월 자동 리셋 — 사용자가 그 시점에 앱을 안 열면 기록을 못 보고 지나칠
  위험 때문에 기각
- 보고 시작일 = 클릭한 날짜(오늘) — 클릭 당일 이전에 이미 완료한 이번 주
  항목까지 같이 사라지는 문제로 기각
