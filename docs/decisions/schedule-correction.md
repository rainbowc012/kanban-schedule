# Schedule correction

## Decisions

- 카드를 잘못 옮긴 직후에는 되돌리기를 제공한다. 이동 알림에 되돌리기 동작을
  붙이고, 실행하면 이동과 그로 인한 일정 구간 변경이 함께 취소된다.
- 이미 지난 오류를 정정하는 경로는 작업 상세(하단 작업 창)다. 선택된 작업의
  일정 구간 목록을 보여주고, 목록에서 개별 구간의 날짜를 고치거나 구간을 지울
  수 있다.
- 달력에 그려진 일정 선을 클릭하면 그 작업이 선택되어 하단 작업 창에 상세가
  뜬다. 그 이상의 편집 동작(삭제 등)은 달력에 두지 않는다.
- 일정 구간 삭제에는 확인 대화상자를 두지 않는다.

## Boundaries

- 이 결정은 일정 구간의 정정에만 적용된다. 작업 자체의 삭제(작업창의 삭제
  버튼)는 별도로 확인 대화상자를 유지한다.
- 되돌리기는 이동 직후 한정된 시간에만 유효하다. 그 시간이 지난 뒤의 정정은
  작업창의 구간 목록을 통해서만 한다.

## Why

한 작업은 일정 구간을 여러 개 가질 수 있어 "그 날짜의 모든 작업"을 나열하는
방식으로는 어느 구간을 지우려는 것인지 모호해진다. 구간은 작업에 속한 데이터이므로
작업 상세에서 다루는 것이 개념적으로 맞고, 여러 구간을 다뤄야 하는 요구를 충족하는
사실상 유일한 자리다.

대부분의 오조작은 이동 직후에 자각되므로 되돌리기가 가장 저렴하게 가장 많은
경우를 해결한다. 되돌릴 수 있는 동작에 확인 대화상자를 두면 반복되는 클릭에
무뎌져 실제 방어력이 약해진다(PRODUCT.md 경험 원칙).

달력 위에서 직접 삭제를 허용하지 않는 것은, 선이 얇고 짧아 조준이 어렵고
구간이 겹쳐 쌓이면 어느 선을 눌렀는지 불확실해지기 때문이다.

## Reconsider when

- 되돌리기 유효 시간이 지난 뒤에 발견되는 오조작이 실제로 잦다고 확인되는 경우
- 한 작업의 일정 구간 수가 늘어나 목록 UI로는 다루기 어려워지는 경우

## Still-rejected alternatives

- 날짜 클릭 → 그 날의 작업 목록 → 삭제 — 날짜 선택이 이미 "주 이동"에 배정되어
  있어 충돌하고, 여러 구간 중 어느 것을 지우는지 모호해 기각.
- 구간 삭제에 확인 대화상자 — 되돌리기로 충분히 방어되고, 확인 창은 반복되면
  방어력이 무뎌진다는 이유로 기각.
