# 칸반 이동에 따른 일정 자동 기록

## User-visible outcome

새 작업을 등록하고 계획⇄실행⇄완료 사이로 옮기면, 이동에 따라 달력에 일정
구간(선)이 그 자리에서 자동으로 열리고 닫힌다. 완료로 옮긴 카드에는 취소선이
표시된다. 사용자는 일정을 따로 입력하지 않는다 — 카드를 옮기는 것이 곧 일정을
기록하는 행위다.

## Approved scope

- 새 작업 등록: 제목, 상세 내용, 이슈/기능 구분, Critical/Major/Minor 심각도를
  입력해 계획 상태로 등록한다
- 칸반 카드 선택과 상세 보기(읽기 전용): 카드를 선택하면 작업 창에 제목·내용·
  이슈/기능·심각도가 표시된다
- 선택된 작업의 일정 구간 목록을 작업 창에 읽기 전용으로 나열 (편집·되돌리기는
  제외 — [schedule-correction](../../decisions/schedule-correction.md) 참고)
- 작업 삭제: 작업 창의 Delete 버튼으로 선택된 작업을 삭제한다. 삭제 전 확인
  대화상자를 거친다 ([schedule-correction](../../decisions/schedule-correction.md)
  의 "작업 자체의 삭제는 확인 대화상자를 유지한다"를 따름)
- 네 방향 상태 이동 전부:
  - 계획 → 실행 (착수)
  - 실행 → 계획 (보류)
  - 실행 → 완료 (완료)
  - 완료 → 실행 (재개)
- 이동에 따른 일정 구간 자동 개폐, 그리고 그 구간의 달력 표시
- 완료 상태 카드의 취소선 표시
- 오늘이 속한 달의 월간 달력 (고정, 이전/다음 달 탐색 없음)
- 새로고침 후에도 등록한 작업과 상태, 일정 구간이 유지됨

## Out of scope for this spec

| 항목 | 이유 |
|---|---|
| 작업 내용 수정(제목·내용·이슈/기능·심각도 변경) | 핵심 기제(이동이 곧 기록)를 증명하는 데 필요하지 않음. 삭제는 이번 스펙에 포함 |
| 일정 구간 편집(되돌리기, 구간 날짜 수정·삭제) | [schedule-correction](../../decisions/schedule-correction.md) 결정을 따라 별도 스펙에서 구현. 읽기 전용 나열은 이번 스펙에 포함 |
| 주간보고 창 | 그 주에 걸친 구간을 상태별로 집계하는 별도 로직이 필요함 |
| 완료 창의 주간 reset, 날짜 선택으로 다른 주 로드 | "이번 주"를 벗어난 조회이며, 이번 스펙은 기록이 만들어지는 것 자체를 증명하는 데 집중함 |
| 월 달력의 이전/다음 달 이동 | 위와 같은 이유로 이번 범위에서 제외 |

## Acceptance criteria

**작업 등록**
- 새로운 작업 버튼을 누르고 제목·내용·이슈/기능·심각도를 입력한 뒤 등록하면,
  계획 열에 제목만 보이는 카드가 새로 나타난다

**작업 선택과 상세 보기**
- 계획·실행·완료 어느 열에서든 카드를 선택하면 작업 창에 그 작업의 제목·내용·
  이슈/기능·심각도가 나타난다
- 선택된 카드에만 이동 버튼이 나타난다. 계획 카드는 실행行 버튼만, 완료 카드는
  실행行 버튼만, 실행 카드는 계획·완료 양쪽 버튼을 가진다
  ([kanban-card-movement](../../decisions/kanban-card-movement.md))

**착수 (계획 → 실행)**
- 계획에 있던 카드를 실행으로 옮기면, 카드가 실행 열로 이동하고 오늘 날짜로
  시작하는 일정 구간이 열린다
- 달력에 오늘부터 시작하는 선이 나타나고, 선 안에 작업 제목이 보인다

**보류 (실행 → 계획)**
- 실행에 있던 카드를 계획으로 옮기면, 카드가 계획 열로 이동하고 열려 있던
  일정 구간이 오늘 날짜로 닫힌다
- 달력의 선은 시작일부터 오늘까지로 고정되어 남는다

**완료 (실행 → 완료)**
- 실행에 있던 카드를 완료로 옮기면, 카드가 완료 열로 이동하고 취소선이 표시되며
  열려 있던 일정 구간이 오늘 날짜로 닫힌다
- 달력의 선은 시작일부터 오늘까지로 고정되어 남는다

**재개 (완료 → 실행)**
- 완료에 있던 카드를 실행으로 옮기면, 카드가 실행 열로 이동하고 취소선이
  사라지며, 오늘 날짜로 시작하는 새 일정 구간이 열린다
- 달력에는 이전 구간(닫힌 선)과 새 구간(오늘부터 시작하는 선)이 같은 작업의
  것으로 함께 보인다

**진행 중인 구간의 표시**
- 아직 닫히지 않은 일정 구간은 달력에서 시작일부터 오늘까지로 그려진다

**작업창의 일정 구간 목록**
- 작업을 선택하면 작업 창에 그 작업의 일정 구간이 발생 순서대로 나열된다.
  각 구간은 시작일과, 닫혔다면 종료일 및 결과(완료/보류)를, 아직 열려 있다면
  "진행 중"임을 보여준다
- 이 목록은 읽기 전용이다. 날짜 수정, 삭제, 되돌리기 등의 조작은 없다
- 일정 구간이 없는 작업(계획 상태에서 한 번도 실행으로 옮겨진 적 없는 작업)은
  목록 없이 표시된다

**작업 삭제**
- 작업을 선택한 뒤 작업 창의 Delete 버튼을 누르면 확인 대화상자가 뜬다
- 확인하면 그 작업이 계획/실행/완료 어느 열에 있었든 칸반에서 사라지고,
  달력에 그려져 있던 그 작업의 일정 구간도 함께 사라진다
- 취소하면 아무 것도 바뀌지 않는다

**지속성**
- 페이지를 새로고침해도 등록한 작업, 각 작업의 상태, 각 작업의 일정 구간
  기록이 그대로 유지된다

## Settled constraints and rationale

- 카드 이동은 선택 후 버튼 클릭으로 하며, 드래그 앤 드롭은 채택하지 않는다 —
  [kanban-card-movement](../../decisions/kanban-card-movement.md)
- 일정 구간은 "실행 상태에 들어오면 열리고 나가면 닫힌다"는 하나의 규칙으로
  통일되어, 네 방향 이동 모두 같은 개폐 로직을 공유한다 (PRODUCT.md 핵심 반복
  구조)
- 카드는 제목만 보여준다. 상세는 작업 창에서만 본다 (PRODUCT.md 경험 원칙)
- 일정 기록은 지워지지 않는다 — 이번 스펙에서는 새로고침 후 유지되는 것으로
  확인한다 (PRODUCT.md 능력 경계)

## Assumptions

- 일정 구간은 일(day) 단위로 기록한다. 하루에 같은 카드가 여러 번 이동해도
  시작·종료는 날짜로만 구분한다
- 달력은 오늘이 속한 달을 고정적으로 보여준다. 이전/다음 달 이동 버튼은 이번
  스펙에 없다
- 한 작업이 가진 여러 일정 구간은 달력에서 각각 별도의 선으로, 같은 작업
  제목을 달고 나타난다. 겹치는 구간이 여러 열에 걸릴 때의 세부 배치(줄 바꿈
  등)는 구현 시 정한다
- 심각도·이슈/기능 선택의 기본값, 폼 레이아웃 등 화면 세부는 구현 시 정한다
- 삭제 확인 대화상자는 브라우저 기본 확인창(confirm)으로 둔다. 디자인이
  입혀진 대화상자가 필요해지면 나중에 바꿀 수 있는 지점이다

## Deferred points

- 작업 내용 수정 UI (삭제는 이번 스펙에 포함됨)
- 일정 구간 되돌리기(이동 직후 토스트)와 작업 창의 구간 목록 편집 —
  [schedule-correction](../../decisions/schedule-correction.md)에 방향은
  결정되어 있으나 이번 스펙에서 구현하지 않음
- 주간보고 창과 그 집계 기준 — 금/월에만 갱신되는 스냅샷이 아니라, 실행·완료
  창의 변화가 실시간으로 반영되는 살아있는 뷰여야 함 (사용자가 주로 금/월에
  "열어 본다"는 것이지, 그때만 "만들어진다"는 뜻이 아님)
- 완료 창의 주간 reset(화요일 경계)과 날짜 선택으로 다른 주 로드
- 월 달력의 월 이동

## Remaining risks

- 이번 스펙에는 정정 수단이 없으므로, 사용 중 잘못 이동하면 되돌릴 방법이
  없다. 다음 스펙([schedule-correction](../../decisions/schedule-correction.md))
  에서 해소될 때까지 남는 위험이다
- 한 작업의 일정 구간이 여러 개로 늘어나고 달력에서 서로 겹치는 경우의 시각적
  배치는 실제로 만들어보기 전까지는 확정하기 어렵다
