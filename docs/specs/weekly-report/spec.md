# 주간보고 패널과 완료 열의 보고 경계

## User-visible outcome

주간보고 패널이 진행·완료·보류 작업을 실시간으로 나열해, 커밋 로그나
메모를 뒤지지 않고 그대로 팀 페이지에 옮겨 적을 수 있게 한다. 완료 열은
기본적으로 아직 보고하지 않은 완료 작업만 보여주고, 주간보고 패널의
Report 버튼을 누르면 이번 주 이전 완료 작업이 기본 화면에서 빠진다.
"전체 보기"를 켜면 언제든 다시 다 볼 수 있고, 달력 주(월~일) 단위
구분선으로 훑어보기 쉽게 나뉜다.

## Approved scope

- **보고 시작일** 개념: 아직 안 보고한 완료 작업과 이미 보고한 완료 작업을
  가르는 날짜. 최초 상태는 "전부 아직 안 보고함"
- **Report 버튼**(주간보고 패널 헤더 우측, 무채색): 누르면 보고 시작일이
  "누른 날짜가 속한 달력 주의 월요일"로 갱신됨. 데이터는 전혀 지우지 않음
- **완료 열**: 기본은 보고 시작일 이후에 완료한 작업만. "전체 보기" 토글로
  전체 표시
- **전체 보기**에서 완료일이 속한 달력 주(월~일)별로 구분선 표시, 최근
  주가 위로 오도록 정렬
- **주간보고 패널**: 진행·보류는 항상 현재 상태 그대로(보고 시작일과
  무관), 완료는 보고 시작일 이후 것만. 각 항목에 이슈/기능·심각도 배지를
  붙이고 심각도 순(Critical→Major→Minor)으로 정렬
- 주간보고 항목을 클릭하면 그 작업이 선택되어 작업창에 상세가 뜬다
  (칸반 카드·달력 막대 클릭과 동일한 선택 동작)
- 보고 시작일은 새로고침해도 유지된다 (localStorage)

## Out of scope

| 항목 | 이유 |
|---|---|
| 날짜 선택으로 다른 주 조회 | [kanban-schedule-recording](../kanban-schedule-recording/spec.md)에서 이미 미룸 |
| 월 달력의 월 이동 | 위와 동일한 이유로 범위 밖 |
| 지난 보고 내용 내보내기/복사 | PRODUCT.md의 미지수 — 사용자가 직접 옮겨 적는다 |
| 보고 시작일을 되돌리는 기능 | Remaining risks 참고. 데이터가 지워지지 않고 전체 보기로 여전히 다 보이므로 되돌리기 없이도 치명적이지 않음 |

## Acceptance criteria

**주간보고 — 진행**
- 실행 열에 있는 모든 작업이 보고 시작일과 무관하게 항상 주간보고의
  "진행" 목록에 나타난다

**주간보고 — 완료**
- 완료 열에 있는 작업 중, 마지막 일정 구간의 종료일이 보고 시작일 이후인
  것만 주간보고의 "완료" 목록에 나타난다
- 보고 시작일보다 먼저 완료된 작업은 주간보고의 "완료" 목록에 나타나지
  않는다

**주간보고 — 보류**
- 계획 열에 있는 작업 중 일정 구간을 가진(과거에 실행에 들어간 적 있는)
  작업이면서, 마지막 구간의 종료일이 보고 시작일 이후인 것만 "보류"
  목록에 나타난다
- 계획 열에 있어도 일정 구간이 아예 없는 작업(한 번도 실행에 들어간 적
  없는 작업)은 목록에 나타나지 않는다

**주간보고 — 표시와 상호작용**
- 각 항목에 이슈/기능 배지와 심각도 배지가 함께 보인다
- 같은 목록 안에서 Critical, Major, Minor 순으로 정렬된다
- 항목을 클릭하면 그 작업이 선택되고, 작업창에 상세 내용이 나타난다
- 칸반에서 카드를 옮기면(진행·완료·보류 상태가 바뀌면) 새로고침 없이
  주간보고 목록도 즉시 바뀐다

**완료 열 — 기본 보기**
- 완료 열에는 마지막 일정 구간의 종료일이 보고 시작일 이후인 완료
  작업만 보인다
- 아직 한 번도 Report를 누른 적 없다면, 모든 완료 작업이 기본 보기에
  나타난다

**완료 열 — 전체 보기**
- 완료 열에 "전체 보기" 토글이 있고, 켜면 보고 시작일과 무관하게 모든
  완료 작업이 나타난다
- 전체 보기 상태에서는 완료일이 속한 달력 주(월~일)마다 구분선이 표시되고,
  그 아래 그 주에 완료한 작업들이 나열된다. 최근 주가 위에 온다
- 새로고침하면 전체 보기는 꺼진 상태(기본 보기)로 돌아간다

**Report 버튼**
- 주간보고 패널 헤더 우측에 Report 버튼이 있다
- 버튼을 누르면 보고 시작일이 "누른 날짜가 속한 달력 주의 월요일"로
  갱신된다. 예를 들어 목요일에 누르면 그 주 월요일로 갱신되고, 월~수에
  이미 완료한 작업은 그대로 완료 열 기본 보기와 주간보고에 남는다
- 버튼을 눌러도 어떤 작업이나 일정 구간도 삭제되지 않는다 — 완료 열의
  기본 보기에서만 빠지고, 전체 보기에서는 계속 보인다

## Settled constraints and rationale

- 진행·보류는 실시간이고 완료만 보고 시작일의 영향을 받는다 — 진행·보류는
  "보고했냐"는 개념이 없기 때문
- Report는 데이터를 지우지 않는다 — 완료 열의 기본 표시 여부만 바꾼다
  (PRODUCT.md "기록은 지워지지 않는다")
- 완료 열의 기본 필터와 주간보고의 완료 목록은 같은 기준(보고 시작일 이후)을
  공유한다
- 보고 시작일은 달력 요일에 맞춰 자동으로 넘어가지 않는다. 사용자가 며칠
  자리를 비워도 그 사이의 기록이 화면에서 사라지지 않아야 하기 때문
  ([report-boundary](../../decisions/report-boundary.md))
- 전체 보기의 주 구분선은 달력 주(월~일)이고, 보고 시작일과는 별개의
  개념이다 — 구분선은 "훑어보기 편의", 보고 시작일은 "무엇이 새 소식인가"로
  서로 다른 문제이기 때문 ([report-boundary](../../decisions/report-boundary.md))

## Assumptions

- "전체 보기" 토글은 새로고침하면 초기화된다
- Report 버튼은 무채색(배경 --foreground, 글자 --background)으로, 지금까지
  쓰인 상태색(초록/파랑/호박/빨강/보라) 어느 것과도 겹치지 않는다
- "전체 보기" 토글은 완료 열 제목("완료") 바로 옆에 둔다. 보고 시작일이
  없으면(한 번도 Report를 안 눌렀으면) 토글 자체를 숨긴다 — 그 상태에선
  전체 보기와 기본 보기가 같아서 토글이 의미가 없기 때문
- 완료 열 헤더의 개수는 지금 화면에 보이는 개수를 그대로 보여준다(기본
  보기면 필터된 개수, 전체 보기면 전체 개수) — 화면에 보이는 것과 다른
  숫자가 나오면 헷갈리기 때문
- 심각도가 같을 때의 세부 정렬 기준(제목순 등)은 구현 시 정한다
- 완료 구분선의 날짜 표기 형식과 세부 스타일은 구현 시 정한다

## Deferred points

- 완료 열·주간보고에서 이번 주가 아닌 다른 주 조회
- 주간보고 내보내기
- Report를 잘못 눌렀을 때 되돌리는 기능

## Remaining risks

- Report를 실수로 눌러도 되돌릴 방법이 없다. 데이터는 안 지워지고 "전체
  보기"로 여전히 다 보이니 치명적이진 않지만, 완료 열 기본 화면에서 방금
  완료한 것들이 갑자기 다 빠져 보이는 순간이 당황스러울 수 있다
- 전체 보기에 카드가 아주 많아지면(수개월 누적) 스크롤이 길어질 수 있음 —
  지금은 페이지네이션 없이 전부 렌더링
